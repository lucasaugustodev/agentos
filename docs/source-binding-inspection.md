# Protected runtime source inspection

The stopped-run inspector has an opt-in, read-only mode:

```sh
node bridge/inspect-stopped-run.mjs <run-uuid> --source-binding <project/workspace>
```

This accepts a managed run UUID and workspace ID, not a filesystem path. It
changes no process, workspace, queue, policy, generation or acceptance. Existing
stopped-run recovery and `--not-started` keep their original contracts.

The runtime already writes `operation-policy.json` exclusively outside the
worker-writable home. Its admission identity names the goal, task, run, fence,
context version and SHA-256 of the workspace marker at dispatch. Inspection
uses that existing authority; it does not create a replacement policy for old
runs.

## Checks and projection

The outer inspector requires the exact run unit to be physically stopped before
and after reading: zero main PID, an unpopulated cgroup, inactive/failed state
and a fresh observation. A remembered stop flag alone is insufficient.

The workspace manager takes its exclusive workspace lock, checks controller
ownership and protected ancestors through `/`, and reads only these fixed files:

- `DATA/worker-runs/<run-uuid>/state.json`
- `DATA/worker-runs/<run-uuid>/operation-policy.json`
- `ROOT/<project/workspace>/.agentos-snapshot.json`
- the existing protected baseline and canonical source inventory

Policy and state must be regular, single-link, controller-owned `0600` files.
The marker must also be protected and single-link. Symlinks, writable ancestors,
duplicate JSON keys and files over 128 KiB are rejected. The source, baseline,
state, policy and marker are checked again before the workspace lock is released.

The result is version 1 and contains:

| Field | Meaning |
| --- | --- |
| `runId`, `workspace` | Requested identity, confirmed against the protected state |
| `state` | Runtime, completed/stopped flags, run fence, workspace and only the two canonical artifact descriptors |
| `admission` | `runtime_operation_policy` authority, goal/task/run/fence/context identity, policy workspace, admission marker digest and raw policy digest |
| `generation` | Workspace, source workspace, base digest, own marker digest and nullable parent marker digest |
| `markerBase64` | Exact fixed marker bytes, after closed-schema validation |
| `legacyParentGeneration` | True when the marker has no parent-generation binding |
| `candidate` | Current base/candidate digest and canonical file hashes; no patch or source contents |
| `process`, `checkedAt` | Fresh physical stop observation after inspection |

`state.artifacts` contains exactly one `candidate.json` and one `changes.patch`,
each projected to `name`, `digest` and `mime`. These names are generated by the
managed runtime after execution stops; worker claims are preserved under other
names. Missing, duplicate or malformed canonical descriptors are rejected.
Other artifact metadata, state bodies, prompts, credentials, environment values
and policy contents are not returned.

The marker's closed schema permits only the fields written by the workspace
manager, including its optional preparation binding. Raw bytes are returned so
a downstream verifier can reproduce the generation digest. Unknown marker
fields are rejected before raw bytes are exposed.

## Two different generation links

`admission.sourceSnapshotDigest` is the hash of the run's **own** marker captured
at dispatch. It must equal `generation.snapshotDigest` observed now.

`generation.sourceSnapshotDigest` is the hash of the **parent** marker captured
when this workspace was prepared. It is nullable for legacy preparations. The
inspector never infers this field from a current parent directory, timestamps,
names, a prior acceptance or recovery artifacts. A missing parent binding must
cause accepted-source chain reuse to fall back to the ordinary planning path.

## Limits of this evidence

The caller must still compare admission goal/task/run/fence/context against a
fresh, complete control-plane snapshot, require current attempt ownership,
accepted producer/QA records, no live actors or leases, and matching immutable
artifact IDs, bytes and hashes. The inspector returns policy context identity;
it cannot decide whether that identity is current in a database it does not read.

Canonical artifact descriptors establish which digests the owning runtime
recorded. They do not replace loading and checking the actual artifacts. Likewise,
canonical source hashing keeps its existing exclusions; it does not certify
assets, evidence, dependencies or other excluded data.

The inspection is not a final acceptance and is not a transaction across the
controller database and remote filesystem. A consumer must refresh stale stop
evidence and use the verified preparation contract to bind a later copy to the
observed source digest and generation. No planner integration or live activation
is included here.

## Validation

The Python fixture uses actual temporary policies, markers, inventories and
locks to exercise sanitization, symlinks, changed fences/context, generation
replacement, legacy fallback and concurrent mutation. The Node fixture checks
both physical-stop observations and preserves the existing recovery contract.
Their Vitest wrapper includes both fixtures in the normal release suite.

## Typed account bridge operations

The same source inspection is available through
`worker.inspectSourceBinding({runId, workspace})`; it calls the existing physical
stop verifier directly, with no shell or caller-selected executable. The typed
controller wrapper is `inspectWorkerSourceBinding` in
`server/workspace-inspection.ts`.

Two additional read-only operations share the protected reader and workspace
locks:

- `worker.inspectGeneration({workspace})`, wrapped by
  `inspectWorkspaceGeneration`, returns version, workspace, generation,
  markerBase64, legacyParentGeneration, candidate inventory and checkedAt. It
  requires no run, does not read a policy, and does not follow the parent. It
  checks the protected baseline and rereads the marker and inventory. It does
  not claim a physical stop for an unknown run; callers still establish current
  controller ownership and absence of live actors.
- `worker.inspectPreparation({workspace, sourceWorkspace, preparationIdentity,
  expectedSourceDigest, expectedSourceSnapshotDigest})`, wrapped by
  `inspectWorkspacePreparation`, validates the exact protected receipt, marker
  and baseline. It returns version, exists=true, workspace, preparationReceipt,
  markerBase64, generation, candidate inventory, destinationChanged and checkedAt.
  It never calls prepare, alters the destination, or rereads the original source.

Requests have closed schemas. Typed wrappers also validate reply identity,
marker bytes/digest, inventory digest, canonical artifact descriptors, receipt
hashes and freshness. They forward transport or reconciliation errors unchanged;
they do not retry.

Preparation absence is explicit: `{version:1, exists:false, confirmed:true,
workspace, preparationIdentity, checkedAt}`. This is returned only while the
workspace and preparation identity locks are held and the destination, baseline,
and all receipts matching either identity are absent. A partial receipt,
conflicting identity, orphan baseline or missing component of an existing
preparation is an error, never confirmed absence. No automatic migration or
repair of protected metadata is attempted.

An unchanged clone has `destinationChanged=false`. A modified clone can still
have a valid initial preparation receipt: inspection reports its current digest
with `destinationChanged=true`, preserving work. First dispatch must require the
unchanged clone. A retry additionally needs the owning controller to verify the
frozen source binding, the previous attempt's admission identity, its confirmed
stop and current ownership. This operation supplies evidence for that decision;
it cannot authorize continuation or final acceptance by itself.

## Terminal admission inspection for retries

`worker.inspectRetrySourceBinding({runId, workspace})`, wrapped by
`inspectWorkerRetrySourceBinding`, is a separate read-only contract for the last
attempt that actually executed. It permits `completed`, `failed` or `cancelled`
with `stopped=true`, and retains the same protected policy, generation, baseline,
inventory and physical-stop checks before and after inspection. Its `state`
projection deliberately contains no artifact descriptors. A failed attempt may
have useful edits without having produced a complete canonical delivery.

The result is evidence of admission and terminality, not accepted-source or QA
evidence. `worker.inspectSourceBinding` remains completed-only and continues to
require both canonical artifacts. A retry consumer must compare the admission's
goal, task, run, fence and context with its frozen previous-attempt identity, and
compare the own generation and candidate digest with the current protected
preparation inspection. It must also retain current controller ownership.

Missing policy, replaced generation, live process, stale observations or a
nonterminal state remain errors. `not_started` does not fabricate an admission;
that distinct path requires the existing confirmed absence/unchanged-preparation
rules. Neither inspector retries commands, modifies source or grants acceptance.
