CONTINUOUS OPERATION WATCHDOG

The manual native cycle "Supervisão contínua — OpenKernel" is the visible owner.
Its active/paused state controls future dispatch. A separate systemd timer checks
registered native executions and official GET-only job results every two minutes.
It does not reactivate an old completed objective or replan its full backlog.

When registered work reaches a confirmed boundary, a native model supervisor
receives bounded measured outcomes, actual independently verified QA JSON and an
immutable artifact catalog. It produces continuation-plan.json. A deterministic
consumer binds the plan to its original evidence, problem scope and source artifact,
then checks current capacity and fixed runtime constraints before creating producer
-> independent QA cycles. Terminal outputs become the next supervisor input. Empty JSON, arbitrary
accounts/workspaces/actions and unverified waiting reasons are rejected.

New reviews persist controller-owned actionEvidence before dispatch. If only another
board changes, an actionable plan can remain valid when its selected boards' source,
QA, results, provenance and ownership are unchanged. Global authority and current
slots, ownership, eligible problems, source boundaries and repair permission are
checked again. Evidence supplied in model output cannot grant this exception; legacy
reviews without the controller proof still require the original global fingerprint.
Same-board or authority changes reconcile existing effects by GET and close only the
unattempted remainder. An uncertain attempted POST retains ownership without resend.

Evidence hashes normalize only known inventories: artifact and occurrence records,
jobs, owners and diagnostic collections are ordered by identity. API list order alone
cannot invalidate a plan. Duplicate records remain visible; CPU cases, instructions,
patch hunks and other semantic sequences are not recursively sorted or deduplicated.

The watchdog also diagnoses ten minutes without published material evidence even
when heartbeats or tool/model responses continue. This is a read-only suspicion:
the supervisor cannot stop, retry or replace a live/uncertain executor. Long calls
can be legitimate. A terminal label requires the native stopped receipt or a
matching fenced HARNESS_STOPPED proof; manual review steps remain owned by their
original controller.

Only authorized Decode, Prefill and Attention experiments are dispatched. CPU
source work is isolated and read-only against the source workspace. Independent
QA remains mandatory. Global model/request capacity stays owned by AgentOS.
Candidate limits prevent accumulating unmeasured variants. GPU CHECK/SCORE is
not automatically authorized by this watchdog; awaiting official measurement is
an explicit state, not a claim of autonomous GPU execution or verified gain.

Durability: persist the approved plan before any dispatch, then persist each
POST intent before I/O. Restart reconciles lost responses using canonical GETs;
it never resends an ambiguous POST. Partial multi-experiment dispatch resumes its
approved action set without treating its own progress as stale external evidence.
Two invalid/failed supervisor revisions for the same evidence reach the explicit
supervisor_failure_needs_repair diagnostic after one corrective review. This is a
bounded failure state, not a promise of unrestricted automatic recovery. A supervisor
response, active timer or executor heartbeat is not a completed material deliverable.

Implementation: scripts/continuity-watchdog.py (Python standard library only).
Tests: python3 -B tests/fixtures/continuity_watchdog_test.py, on server only.
Registration and state contain private operational metadata and stay outside Git.
Deploy a root-owned immutable script, root-only registration and state directory.
Service uses User=root explicitly because the official CLI resolves its signed-in
profile through that identity. Credentials are read by the trusted controller,
never placed in worker prompts, outputs, command arguments or event artifacts.

Qualification must distinguish: timer active, observation succeeded, supervisor
dispatched, native attempt running, plan consumed, producer/QA dispatched, and an
actual accepted/benchmarked outcome. Unit tests are not proof of live autonomy.

Planning input separates named official incumbent benchmarks from available
candidate source artifacts. An unknown incumbent source stays unknown and cannot
be selected as an experiment base. Test/benchmark counts come from official
record events per board. Full receipts remain protected and hash-addressed;
successful log tails are omitted from the next model input. Root-pinned comparison
context supplies compact measured profiles, uncertainty and next hypotheses.

An optional root-owned official-check registry can register diagnostic jobs from
a separately authorized adapter. The reader verifies native occurrence ownership,
confirmed stop, current source/QA artifacts, successful source-bound QA, wrapper
receipt identity and the exact CHECK transport receipt. Native dispatch provenance
(dispatchReceiptSHA256) and GPU transport digest (transportReceiptSHA256) are
separate. Registered results wake the next supervisor after their actual terminal
status; this reader never authorizes or sends an official POST itself.

Future experiment templates request reproducible one-file patches and explicit
CPU checker/result hashes, cases, negative controls and limitations from both
producer and independent replay. Older running cycle definitions remain intact.
Missing evidence is a blocked qualification, never permission to assume it passed.

Registry tests need a root-owned temporary directory with protected parents.
Set TMPDIR to a dedicated root-only test directory on the server; do not change
ownership or permissions of a shared build directory to make these tests pass.

The optional adapter status reader checks its root-owned policy, current watcher
code/config pins, freshness, native occurrence, source and QA artifact identities.
Controller/storage/transport failures, quota and uncertain effects never authorize
kernel evidence repair. Missing evidence can produce a fixed repair_evidence cycle:
the candidate and original base stay byte-identical, previous checker/results come
from the same original producer attempt, and a new independent QA replays the work.
Semantic/numerical failures require a new code hypothesis instead. Two unsuccessful
repairs isolate that candidate with an explicit repair_exhausted diagnostic; no
third repair is enqueued, while other eligible sources remain available. Disabled
or inactive adapter policy provides diagnostic information only, never repair authority.

Transport-only patch normalization accepts only one file with either canonical
headers or that board's exact kernel submission headers. It changes just those two
headers, applies every hunk in memory, and requires exact candidate bytes. Original
patch, canonical patch and application proof retain separate hashes. Arbitrary,
truncated, multi-file or divergent patches cannot use this repair action.

Material age derives from published artifacts or completed native stages and is
reported separately from controller dispatch age. A diagnostic call cannot reset
material age. Files still being built inside an active workspace are not published
progress, and this limitation is explicit in the supervisor input.

A changed supervisor prompt requires updating the existing native control cycle
through PUT /api/cycles/:id with its expected version before installing matching
controlDefinitionSHA256/controlVersion configuration. Never create a replacement
control cycle or mutate active occurrence snapshots. Wait until no supervisor plan
is pending, preserve prior config/code receipts, and validate the next actual native
dispatch uses the new definition. Tests cover stale version rejection and preserved
old snapshots; deployment still requires a separate live verification.

Published producer verification and CPU results now carry bounded semantic evidence
into the next supervisor input. The reader binds both reports to the latest produce
attempt, its immutable input source, candidate and checker bytes. Invalid JSON,
conflicting hashes or attempt identity produce a local diagnostic without copying
unvalidated report text or stopping observations of unrelated work. A reported
falsification remains negative_result_reported, never QA acceptance or GPU proof;
CPU success alone does not imply a useful code change or measured improvement.

Authenticated adapter NO_EXECUTABLE_CHANGE or NO_CANDIDATE_CHANGE rejections require
a new hypothesis. Only that candidate is isolated from selection, while the original
source and other eligible work remain available. Such rejections never authorize an
evidence-only repair, override active QA, or change existing occurrence snapshots.

New supervisor inputs include sourceCapsules in the existing local cycle-input.json.
The model prompt contains the input path and hash, not the source bytes. The controller
fetches and verifies selectable terminal sources; the supervisor decodes only needed
files into data/sources and navigates a bounded static AST index. The old workspace
baseline/submission is not a substitute for the selected artifact. No network,
credentials, new agent stage, backend change or native control version is needed.

Capsules preserve artifact aliases while sharing bytes by problem and digest. They
prioritize the best measured available source, its known parent, and the most recent
available candidate and its known parent, followed by other confirmed sources.
Recency uses verified material progress as well as completion time, since failed
deliveries can have no occurrence completion timestamp. Recency does not imply
usefulness, acceptance or correctness. A benchmark with unknown
source remains a benchmark, never an available incumbent. Limits are 256 KiB per
source, 1 MiB total raw source and 2 MiB for the complete input, including existing
context and metadata. Omitted sources have explicit identities, counts and reasons;
they are removed from that review's selectable catalog. Missing/corrupt sources do
not grant inspection or dispatch authority. If no eligible source can be supplied,
the controller reports supervisor_sources_unavailable without spending a model call.

Plan validation checks the selected artifact against the exact capsule bytes and
hash stored in the review input, then checks the current catalog, ownership and
capacity before dispatch. A retry reuses the original persisted POST body. Existing
pending reviews retain their original input contract; their effects are reconciled
using the existing ownership rules. Sources and AST indexes are untrusted data and
navigation aids: providing bytes does not prove the model read them or establish
semantic novelty, correctness or performance. Independent QA and the no-op GPU
admission guard still apply. Measure the effect on redundant proposals and accepted
executable candidates before claiming improved productivity.

QA defects travel with their source

qaEvidence preserves complete structured blockingFindings from an artifact whose
bytes, hash, latest attempt and candidate identity have been checked. The parent
source is checked when the native input supplies it. This is a bound QA report,
not acceptance or a guarantee that its claims are correct. Missing blockers are
marked not_reported; malformed, cross-candidate, corrupt or oversized reports
produce an explicit local diagnostic with no unverified report text. Limits are
64 KiB per QA report, 32 blockers and 32 KiB for the complete blocker array. No
blocker is silently clipped. Legacy findings/limitations summaries explicitly
mark truncation, while the complete blockers remain separately available.

The planner receives that evidence with the outcome. When it selects a source,
the same occurrence/candidate-bound structure is also delivered as
input.experiment.sourceQAEvidence to its worker. Canonical source and policy
materials remain unchanged. Workers report conflicts between the scoped task and
known blockers instead of silently losing the report. Registered experiments require
the exact independent-qa step definition, latest attempt and confirmed stop boundary;
the envelope includes stepId, stepKey and runFence. A producer cannot publish a file
with the QA name and acquire QA provenance. Legacy reports explicitly say that
independence is not established. Legacy string blockers retain their full text and
receive identities derived from array index and text hash, never invented semantic IDs.

Immediate continuation after closed administrative transitions

One tick can process up to three stale_plan_superseded, supervisor_failed or
supervisor_plan_rejected transitions. After each, it checks the native control
and observes current evidence/ownership again, under the same existing process
lock. It can then dispatch one new supervisor review without waiting for another
timer interval. A dispatch, active owner, real wait, pause or exception ends that
invocation. Transport errors are not retried inside the drain. Existing review
failure limits, request identities, uncertain-effect GET reconciliation, WIP,
source/authority gates and official policy remain unchanged.

POST reconciliation is deliberately not an administrative drain state: even a
reconciled create with no run remains a separate boundary. The compact continuation
status records the transition count, up to three state/occurrence/code references,
the final wait reason and next action. Reaching the bound persists an explicit
administrative_transition_limit status; already closed transitions remain saved
and the next normal tick can resume. This is a scheduler-latency improvement,
not evidence of useful kernel performance or complete autonomous recovery.

Known separate limitation: when evidence returns to a historical fingerprint,
the existing request key can acknowledge a formerly superseded review. The
A-to-B-to-A regression test proves this patch stops after one acknowledgement,
does not resend a POST or dispatch an experiment in that invocation, and does
not loop. It does not claim to repair the broader historical-review identity
problem. Changing those keys or recovery semantics requires a separate change.
Native repair evidence is selected only from the authenticated current producer
step/attempt, with its definition, manifest, fence and confirmed stop. An
independent QA attachment named cpu-result.json cannot replace or duplicate the
producer's report. Missing, ambiguous, oversized or malformed native envelopes
withhold only that repair action and keep its reservation; other boards and
their pending plans can continue. Global policy, configuration and external
owner checks remain strict. The qualified snapshot includes a QA report with
an independently produced CPU result and a producer report above the existing
size limit: selection is corrected, the limit remains enforced locally.

Mixed action plans (explicit planVersion=2)

A version-1 plan chooses one global mode. Selecting evidence repair therefore
prevents the same review from requesting independent code experiments. Version 2
uses decision=actions and an explicit kind on every entry: experiment or
repair_evidence. Both can coexist in one bounded plan. Each repair still requires
the exact authorized target, immutable candidate/patch and independent replay/QA;
ordinary code work retains its own source, scope and acceptance checks. Per-action
source proofs select the appropriate experiment or repair hash. Unknown POSTs
continue through GET-only reconciliation, including a lost repair acknowledgement
after an ordinary experiment was already dispatched.

Every boardAvailableCandidateSlots key requires one capacityReview entry with the
observed availableSlots, exact plannedActions count and a short factual reason.
The counts describe the immutable planning input; fresh admission independently
checks current capacity. Reasons are model judgments, not deterministic proof of
novelty or exhaustion. The supervisor must consider every board, mix urgent repairs
with independent hypotheses, and avoid waiting for a different candidate's GPU
result when its proposed CPU work does not depend on that result. Capacity alone
does not justify filler work or waive any correctness gate.

reviews and request bodies are not rewritten or silently promoted. A new manual
control cycle permits a reversible pin handover without changing in-flight
occurrences. Do not roll back to an old reader while version-2 plans still require
reconciliation: preserve a compatible reader and the current complete state.

# QA report reader compatibility

Registered diagnostic CHECKs and repair classification read authenticated QA
reports up to 1 MiB, matching the native adapter artifact budget. A legitimate
report larger than 32 KiB therefore no longer stops observation of all boards.
The reader requires the complete declared bytes and digest, an object root,
unique JSON keys, and finite numbers, including exponent-overflow rejection.
Registry ownership, latest attempt, source/candidate lineage, exact boolean
acceptance fields, and registered transport/receipt bindings remain mandatory.

This is a raw-reader limit, not extra authority or extra model context. The
64 KiB QA context and 32 KiB prior-QA repair diagnostic limits remain separate.
Large authenticated reports use the bounded historical projection described below.
Oversized, corrupt, unbound or malformed registered QA still fails closed; it is
never skipped to free ownership or manufacture acceptance. No official action
or performance improvement is implied by reading a registered CHECK report.

Board-scoped planning and deterministic replenishment (opt-in)

Set plannerMode="board-lanes-v1", targetNativeWorkers=8 and
readyLowWatermark=2 with planVersion=2 and pipelineCapacityVersion=2. This
requires a newly registered/pinned supervisor definition with concurrency3.
Experiment cycles retain concurrency1. Without the opt-in, the single-planner
contract and existing behavior are unchanged.
Once lane records/outboxes exist, the reader requires this plannerMode. Removing
the flag or downgrading to an older reader is not a supported rollback: it would
hide ready reservations. Hold the new controller if recovery is needed; preserve
its current state, inputs and intents. A pre-resume rollback must prove that no
lane request or outbox was created before restoring the original configuration.

One watcher owner under watch.lock manages three independent planner lanes:
Decode, Prefill and Attention. Each planner receives only its board's source
capsules, outcomes, diagnostics, official jobs and recent dispatches. Scoped
request namespaces include board, authority and evidence identity. Validators
reject cross-board actions; a slow planner cannot hold up the other two lanes.
No fourth LLM manager is added. The deterministic sweep owns replenishment.

The sweep first reconciles all attempted review/action effects using their
original identities, then collects all finished plans, admits and validates
the ready buffer, dispatches ready actions, and finally replenishes planners.
An uncertain POST prevents new writes globally until GET reconciliation proves
its result. A lost ACK never authorizes retransmission. A legacy global planner
may finish naturally in the spare session; its old-authority plan cannot be
newly dispatched under the changed contract. Its effects and output references
remain recorded. Additional legacy planners reduce the effective worker target.

approvedPlan is the immutable proposed batch; its persisted outbox records
unadmitted, ready, dispatching, owned or invalidated states per action. Ready
actions reserve the global24/per-board8 pipeline budget and exact normalized
hypotheses before any create/run request. A changed source invalidates the
affected unstarted action; acknowledged effects remain owned. Ready repairs
cannot duplicate another repair's fixed candidate output. Archived inputs and
POST receipts retain their existing byte identity and integrity checks.

The target is8 native worker reservations, counting queued/running/unconfirmed
production and QA. At most3 new experiments are dispatched per sweep, with
fresh observation before each action; this bounds expensive observation/API
work while the ready buffer survives between sweeps. With a private30-second
timer, an initially empty pool can fill in3 sweeps when work is admissible.
The native cycle engine already claims queued work every2 seconds. GPU waits
still count against24/8 but do not count as ready CPU work or native workers.
Planning replenishes below2 ready actions per board when sources, capacity and
existing failure rules permit. Eight workers plus3 planners leave1 session for
handover within the deployed12-session ceiling; the global6-request gate is
unchanged. External account occupancy can reduce actual concurrent execution.

Status distinguishes nativeReserved, nativeQueued, nativeExecuting,
plannerPending, legacyPlannerPending, readyActions/readyByProblem and GPU or
other waiting pipelines. An admitted proposal or queued occurrence is not a
running session, accepted delivery or performance gain. Explicit per-board

Authenticated large-QA context

QA artifact admission remains limited to 1 MiB of original bytes, with exact
size/SHA256 verification and strict JSON: duplicate keys, nonfinite numbers,
numeric overflow and non-object reports are rejected. Context presentation is
separate: source QA envelopes remain at most 64 KiB and prior-QA repair
diagnostics at most 32 KiB. Candidate/source, latest attempt, independent QA
step, stopped boundary, fence and manifest bindings remain mandatory.

Small historical reports stay complete in repairQADiagnostic.report. Larger
ones carry reportProjection.version=1 and complete=false. Critical flags and
hashes remain exact; retained fields/sections are complete values with original
array order. Omitted fields have JSON-pointer, byte-count and digest references,
with explicit reference coverage and array counts. No partial cases array is
presented as a complete report. Decisions continue to read the full strict QA;
a projection is never current acceptance, official authority or a QA artifact.
Hash domains are explicit: artifact.digest covers original raw bytes;
reportSHA256/reportBytes and omitted-field references cover canonical JSON of
the original strict report (original_strict_json_canonical). In contrast,
selectedReportSHA256 and each section.valueSHA256 cover the transported value
after the versioned json-numbers-v1 normalization. Their canonicalization
markers prevent integral floats or signed zero becoming integers in the API
from invalidating a context hash. Verify original references from the supplied
original bytes, not by hashing a projection or normalized partial reconstruction.

Projected repairs also receive prior-qa-original.json as a separate material in
input.experiment.materials. This contains the complete original bytes/base64,
artifact/attempt identity, size and SHA256, revalidated before any create/run
POST. Workers must inspect omitted findings/cases in that material and produce
fresh complete evidence. The independent QA step and finalizer still require
the full new report; its existing artifact limit is 1 MiB, not the 32 KiB inline
context budget. Neither original artifacts nor historical request bodies are
rewritten or reconstructed from a projection.

Complete blockers are never clipped. If blockers or their envelope cannot fit,
context remains unavailable and repair authorization stays closed. Once the
original full report has passed its identity/byte guards, that internal report
still informs completed-work ownership: a presentation error must not turn an
occupied native-to-unmeasured pipeline into a free slot. Invalid bytes/bindings
do not obtain this internal identity guarantee. Existing semantic rejection,
repair exhaustion, quotas, capacity, unknown-effect reconciliation and approval
rules remain unchanged.

Qualification runs only on an isolated server with in-memory transports. It
includes exact raw-size bounds, malformed JSON, scope/fence/manifest failures,
large-context ownership, immutable original-material handoff and independent QA.
A private frozen replay additionally compares the old and new readers on real
size-blocked owners without native/official network calls or operational writes.
Private inputs, identities and execution evidence are not part of this repository.

CPU admission while official quota is unavailable

Capacity v2 distinguishes a proven preflight resource wait from an uncertain
execution. Only authenticated CHECK_QUOTA status with postAttempted=false,
jobId=null and the exact candidate/occurrence in the source catalog qualifies.
The adapter emits that marker only after ruling out durable uncertain effects
and before creating any submission intent. Missing or legacy markers, unknown
actors, uncertain receipts, other rate states and unregistered running checks
continue to block their board.

The quota candidate keeps its original WIP reservation, source identity and
hypothesis reservations. Independent CPU work may use remaining real capacity;

no counters, ownership or historical reports are rewritten to open a slot.

Historical QA CPU-binding conflicts (2026-11-02)

A historical QA report can quote stale checker/result hashes even when the
bound producer artifacts are intact. Evidence repair may now describe this
specific conflict without accepting or rewriting the QA. Both reported hashes
must be well-formed SHA256 values and at least one must differ. The producer CPU
candidate/checker bindings must match exactly; its checker, result, verification,
candidate, base and applicable patch bytes retain their existing identity and
attempt/fence/manifest guards. Producer verification must bind the exact base
and candidate and report the required scope/passed/no-GPU/no-official flags.
QA semantic flags must be strict booleans, positive, without blockers or claims
of proven GPU performance. Missing producer hashes or contradictory producer
evidence do not qualify for this path.

The bounded repairQADiagnostic carries evidenceBindingConflict with the original
QA artifact reference, reported hashes, actual producer artifact references and
the conflicting field names. currentAcceptance and originalReportBindingValid
remain false. The report is preserved exactly, including its incorrect claims;
projection and full-original attachment rules remain unchanged. The marker adds
instructions only to that new repair execution: keep candidate and canonical
patch immutable, rerun CPU, and obtain a new independent QA that references the
actual new checker/result bytes. Existing definitions without this marker remain
unchanged. No conflicting QA is admitted to official checks by this feature.
